# InsightCut：Video-first 真正 AI 视频生产（替代图片+配音成片主线）

## 架构选择

InsightCut 上游默认是一条「脚本 → 句子分段 → 图片 + TTS → 静态动效+旁白 MP4」流水线。那是一种知识口播视频生产方式，**不是**本项目目标的真正图生视频连续镜头。它保留作为老项目兼容模式。

我们当前的默认新项目模式：

1. **Qwen 故事导演**：根据主题或剧本确定每个镜头的实际可视内容，以及长期 IP 的统一服装、脸型、背景世界观。
2. **百炼万相生图**：每个镜头生成首帧并本地存档。
3. **万相图生视频**：把**每个首帧**变成 5 秒（第一版）的真实动态 MP4；每镜头使用导演给出的动作/运镜提示词。
4. **视频素材验收**：每段视频有独立存储、状态检查、失败重试和因源图片改变而失效的机制。
5. **FFmpeg 视频拼接**：画幅、FPS 和编码规范化后按照分镜顺序硬切合并成完整 MP4。**这里不读取旁白和静态图片作为视频镜头，更不会回退 Ken Burns。**

> 现阶段 2～5 镜头的短片更适合真实 API 验收。第一版为保护用户试验额度限制最多 12 个分镜，暂未支持上百镜头和自动转场匹配。

## 配置

百炼文案模型示例：`qwen3.8-flash`；图片示例：`wan2.7-image`；视频示例：`wan2.6-i2v-flash`。

业务空间 API URL 分为两套：
- LLM：`https://YOUR_WORKSPACE.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`
- 图像和视频：`https://YOUR_WORKSPACE.cn-beijing.maas.aliyuncs.com/api/v1`

Video-first 支持从后台设置的阿里云 LLM/图片凭证复用 Key 和专属域名，或读取本地环境变量 `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`。Key 只保存在本机，不提交到 GitHub。

不用配置豆包或 MiMo。旧界面及素材表仍需音频文件才能保持兼容，这时选择 `silent:default`，本地仅生成不出声的时间轴文件；**最终 AI 动态成片完全不读取该音频文件**。

## 创建和生成

1. 在「创建视频」选择默认 **无旁白（AI 视频优先）**，输入故事或主题，选择固定 IP 和画面风格，生成分镜规划。
2. 在工作台检查分镜文字、画面提示词、人物一致性；推荐修改过长的分镜数量到 2～5 个。
3. 点击工作台底部 **生成全片 AI 动态视频**，明确阅读付费确认。付费调用必须由用户主动确认；页面会提示镜头数及单镜头时长。默认每镜头 5 秒。
4. 后端先完成分镜图片，再对每个镜头调用百炼万相异步 I2V。状态、模型 task_id、已生成 MP4 保存在 `data/media/_shot_videos/{task_id}/`。
5. 生成成功后，拼接结果保存在 `data/media/_video_first/{task_id}/video_first.mp4`。可以通过工作台顶部 **真实 AI 视频生产** 面板直接预览/下载，标准预览/导出也会优先使用同一动态成片。
6. 一旦任一镜头失败，任务停止且已经完成的镜头仍保留。可先单独修复某个镜头，再恢复整片生产；**不会自动生成静态图替代镜头**。

另有快捷入口：如果分镜图片已经齐全，顶部面板也支持单独发起全片图生视频，生成真正动态 MP4，不依赖旧流程的 TTS 状态。

## 限额、费用和恢复

- 发起批量图生视频前必须显式确认计费，支持 5/10/15 秒（自动流水线固定 5 秒）。
- 每个模型任务完成前，不将远端 URL 当作有效本地文件；成功下载后才标记 `completed`。
- 单分镜任务含 provider task_id，断线或后端重启后用户恢复时优先轮询原任务。若远端确实失败，再次**重新提交**可能产生额外费用，须明确勾选。
- 每个镜头首帧变化、分镜文案变化、画幅变化、视频素材变化会使最终成片标为过期，避免返回旧视频。
- 整片拼接成功会执行 FFprobe 验收，确保输出是视频且有合理时长。错误不删除已成功的视频片段。
- GitHub 测试环境**没有模型 Key**：只测试模拟 provider、真实 FFmpeg 拼接、图片与视频失效、幂等，以及前端构建。实际万相调用需要本机验证权限与剩余额度。
- 本次 MVP 的**默认画面**是真正的视频模型生成的片段；**配音/字幕/BGM** 都是未来独立的可选后期工序，而非生产主线。
